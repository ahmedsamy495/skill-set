# RFC 7807 Problem Details Standards

To ensure predictable client error handling, all API error responses must adhere to the **RFC 7807 (Problem Details for HTTP APIs)** specification.

## Response Header
```http
Content-Type: application/problem+json
```

## Standard Payload Schema

```json
{
  "type": "https://api.example.com/errors/invalid-parameters",
  "title": "Invalid Parameters",
  "status": 422,
  "detail": "One or more input fields failed validation rules.",
  "instance": "/api/v1/users/register",
  "code": "ERR_VALIDATION_FAILED",
  "invalidParams": [
    {
      "field": "email",
      "reason": "Must be a valid email address with an active MX record."
    },
    {
      "field": "password",
      "reason": "Must be at least 12 characters long and contain a special character."
    }
  ]
}
```

## Standard Fields Breakdown

- **`type`** (URI reference): Unique URI identifying the problem type.
- **`title`** (string): Short human-readable summary of problem type (must not change from occurrence to occurrence).
- **`status`** (integer): The HTTP status code generated by the origin server.
- **`detail`** (string): Human-readable explanation specific to this occurrence.
- **`instance`** (URI reference): Identifies the specific endpoint invocation.
- **`code`** (string, optional extension): Machine-readable error code for client switch-case handling (e.g. `ERR_USER_NOT_FOUND`).
- **`invalidParams`** (array, optional extension): Detailed list of field-level validation errors.
